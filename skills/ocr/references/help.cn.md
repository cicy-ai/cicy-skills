# ocr — 命令参考

## 识别（默认命令）

```
ocr <image…> [options]
ocr recognize <image…> [options]   # 显式形式
```

将识别出的文本输出到 **标准输出**（每个检测到的文本框一行，按引擎返回的左上角阅读顺序排列）。错误和单文件处理失败信息输出到标准错误。当处理多个输入文件时，每个文件前会加上 `── <path>` 前缀。

| 选项 | 含义 |
|---|---|
| `--json` | 完整结果：`{"<file>": {"boxes": [[x, y, text, score], …]}}` — 其中 x/y 为文本框左上角的像素坐标 |
| `--joined` | 以无分隔符方式连接所有文本框文本（用于与期望字符串进行匹配） |
| `--min-score <0-1>` | 丢弃置信度低于此值的文本框（默认 0 = 保留全部） |

批处理模式：单次调用中的所有图像共享一次引擎加载（约 2 秒）；
后续单张图像识别速度较快。损坏/无法读取的图像会报告到标准错误并继续处理批处理任务（最终退出码为 1）。

## 安装

```
ocr install
```

1. 如果已存在可用的 Python 环境（虚拟环境，或系统 python3 可导入 `rapidocr_onnxruntime`）→ 完成，幂等操作。
2. 否则创建 `~/.cache/ocr-skill/venv` 并通过 pip 安装
   `rapidocr_onnxruntime` — 优先尝试 `$OCR_PIP_INDEX`（如已设置），然后尝试 PyPI，最后尝试 tuna 镜像源。

Debian/Ubuntu 前置要求：`sudo apt install -y python3 python3-venv`。

## 状态

```
ocr status
```

显示已解析的解释器路径、rapidocr 可用性、是否来自专用虚拟环境或系统 Python，以及虚拟环境路径。

## 退出码

- `0` 成功
- `1` 运行时故障（未安装、运行器崩溃或批处理中 ≥1 张图像处理失败）
- `2` 用法错误（无输入文件/缺少输入文件、未知选项）
- 运行器内部错误：`3` = rapidocr 导入失败（作为普通错误显示）
